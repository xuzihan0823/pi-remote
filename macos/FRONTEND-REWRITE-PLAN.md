# Pi Remote macOS 前端重写执行方案

版本：1.0 · 2026-09-18  
交付对象：负责实现的 AI / SwiftUI 开发者  
项目：`/Users/mac/Desktop/pi-remote`  
目标应用：`macos/` 下的原生 Pi Remote 助手。本方案不包含 iOS 客户端重写。

## 1. 任务与最终效果

把现有“配置表单 + 状态卡片 + 常驻日志”的界面，重写为一款精致、清晰、适合长期使用的 macOS 连接工具。用户打开后，应立即知道当前是否可以用手机连接、需要完成什么操作，以及出现问题后从哪里处理。

设计方向确定为 **暖白与深绿的原生桌面连接台**。沿用现有 π 标志，以偏暖的浅色背景、深绿操作色、精确排版、轻量材质和少量状态动画形成识别度。视觉重点是右侧“本机 → 中转服务”的连接轨迹与扫码区域。

成功交付是能构建、能真实连接的 SwiftUI 应用，包含完整的未连接、连接中、已连接、恢复中、停止中、错误状态，以及深浅色和减少动态效果适配。所有按钮必须有实际行为。

本次不增加聊天、会话管理、多服务器管理、延迟监测、设备管理、账户系统或开机自启开关。2026-09-26 起新增两项范围：服务器模式下"一键部署 Relay 到自己的服务器"，以及运行时 pi / omp 选择，详见第 14 节；第 14 节与前文冲突时以第 14 节为准。现有服务没有提供的数据不得用于装饰性指标。

## 2. 已核实的工程事实

以下为方案编写时的源码事实，实现前应核对最新代码，保留其他人的未提交修改。

| 技术 | SwiftUI + AppKit，SwiftPM，最低 macOS 13 | 保持原生实现与最低版本；不引入 Electron、WebView 或前端框架 |

| 服务地址 | 默认 `wss://pi.anyyu.cyou/ws/agent`，允许用户更改 | 默认值保留，不能把所有服务器都命名为“东京” |

## 3. 视觉规范

### 3.1 气质与材质

- 以实色表面、留白和细分隔线建立层级。只有窗口顶部允许使用轻量系统材质；表单和二维码始终使用稳定底色。
- 左栏略深于主画布；右栏有一个主要扫码容器，避免把每句话都装进卡片。
- 深绿只用于主要动作、已通过状态和选中项。错误用明确的红色，等待与恢复用琥珀色。
- 不做大面积炫光、动态渐变背景、悬浮粒子、视差、持续呼吸的成功状态或反复弹跳。
- 原生交通灯、窗口拖动、文本选择、输入法、上下文菜单保留系统行为。

### 3.2 颜色 Token

### 3.3 字体、间距、圆角

这是原生 macOS 工具，沿用项目系统字体：拉丁字符用 SF Pro，中文由系统回退 PingFang SC；代码路径与日志用系统等宽字体。品牌识别来自现有 Logo、构图和配色，不额外下载字体。

## 4. 窗口与信息架构

默认内容区 1040 × 720 pt，最小内容区 900 × 640 pt。尺寸以 SwiftUI 内容区域为准，标题栏由系统额外管理。保留原生标题栏，内部顶部栏高 56 pt。

```text
┌────────────────────────────────────────────────────────────────┐
│ 原生 macOS 标题栏 / 交通灯                                      │
├────────────────────────────────────────────────────────────────┤
│  π  Pi Remote                         [状态 pill]   [诊断 ⌄]     │ 56
├───────────────────────┬────────────────────────────────────────┤
│  连接设置             │  已准备好，随时连接                     │
│  [服务器 | 临时隧道]  │  打开 iPhone 上的 Pi Remote，扫描下方码。│
│                       │                                        │
│  服务器地址           │       [本机 Mac] ───── [中转服务]       │
│  [wss://…          ]  │                                        │
│  连接密钥             │      ┌──────────────────────────┐      │
│  [••••••••         ]  │      │       用手机扫码          │      │
│                       │      │      ┌────────────┐      │      │
│  工作区               │      │      │  QR 码     │      │      │
│  [📁 Desktop    …  ]  │      │      └────────────┘      │      │
│  ▸ 高级设置           │      │  连接码仅供自己的设备使用 │      │
│                       │      └──────────────────────────┘      │
│  [连接 / 断开连接  ]  │  pi.anyyu.cyou             [复制地址]   │
│  从 .env 导入         │  运行于本机 · Desktop                   │
├───────────────────────┴────────────────────────────────────────┤
│  ▸ 诊断 · 最近一条运行记录                                      │ 36
└────────────────────────────────────────────────────────────────┘
```

- 左侧固定 340 pt，右侧弹性填满。最小宽度时右侧有 560 pt，扣除内边距后约 496 pt。
- 右侧内容最大宽度 640 pt并居中；扫码容器最大宽度 440 pt。宽窗口避免无限拉长控件。
- 左栏表单可单独滚动，底部主要操作固定在左栏底端，容器高度不足时仍可触达。
- 右栏可滚动；诊断折叠时，默认尺寸应完整看到主标题、二维码、地址与工作区摘要。最小尺寸允许辅助信息滚动，但不能裁切二维码。
- 底部诊断跨两栏，默认折叠为 36 pt；展开后总高约 200 pt，不改变窗口外部尺寸。上方区域缩小并可滚动。
- 页面宽度不足最低值时交给原生窗口限制，不增加手机式单栏断点。
- 初次进入和后续连接成功均保留同一套空间结构，避免整个界面突然换位。

## 5. 各区域具体交互

### 5.1 顶部栏

左侧显示 24 pt 品牌标志与 Pi Remote；右侧为状态 pill 和“诊断”切换按钮。按钮与底部诊断入口控制同一个展开状态。

状态 pill 使用“图标 + 文案”，不只靠颜色。在线用对勾，待机用空心圆，处理中用静态连接符号，错误用感叹号。等待动画集中在右侧路线；路线不可见时才用小型 ProgressView 替代，避免多个旋转指示器同时运动。不要加入网络测速、设备数或实时钟表。

### 5.2 左侧连接设置

模式切换为双选项分段控件：“服务器”“临时隧道”。每项视觉宽度相同，选中背景滑动；兼容 macOS 原生键盘和 VoiceOver。底层仍映射 `.server` 和 `.cloudflare`。

服务器模式按顺序显示：

1. **服务器地址**：单行输入完整 `/ws/agent` 地址；获得焦点时显示清晰边界，长地址允许横向编辑。
2. **连接密钥**：SecureField，辅助文本“连接时保存到系统钥匙串”。默认不提供明文展示和复制按钮。
3. **工作区**：文件夹图标、可编辑路径、“选择…”按钮。可展示缩略路径，但编辑和底层保存必须使用完整路径。
4. **高级设置**：默认折叠，包含“pi 可执行文件”及 `PI_BIN` 辅助标签、当前完整路径、说明“通常无需修改”。路径不合法时自动展开并定位字段。

临时隧道模式用一块约 104 pt 高的说明区替代服务器地址和密钥字段，标题“无需配置服务器”，正文“自动生成临时公网地址；重新连接后，请用手机重新扫码。” 提供轻量“由 Cloudflare 提供隧道”标识。工作区和高级设置位置顺延，Token 保持现有自动生成逻辑。

连接中、恢复中、停止中、已连接时，配置均依照 `canEditConfig` 禁用；锁定时字段文字保持可读，不把整个栏位淡化至难以识别。在栏位标题下显示“断开后可修改配置”。

底部操作：未连接显示绿色“连接”；连接中显示次级“取消连接”；已连接显示描边“断开连接”；恢复中显示“停止重连”；停止中显示禁用的“正在断开…”。所有动作调用已有 `connect()` / `disconnect()`，不自行启动或终止进程。

“从 .env 导入”作为次级入口放在主操作下。仍使用 NSOpenPanel，并显示隐藏文件。导入成功显示本地短提示“已导入服务器、密钥与工作区，连接时保存”；实际导入项由真实结果决定，跳过的值持续可查。不要把“已导入”表现为“已连接”。

校验在字段失焦或点击连接时触发；不要用户每输入一个字符就报错。复用现有 EndpointValidator 与路径检查，禁止另写一套不一致的 URL 规则。字段错误紧随字段展示，全局错误放在右侧主状态下。路径存在性和可执行检查仍由连接前置检查负责。

### 5.3 旧服务提示

检测到旧服务时，在左栏模式控件之前显示琥珀色横幅：

> 检测到后台连接服务  
> 接管后，由此应用维持连接。退出应用后，旧服务不会自动恢复。

提供“接管服务”“重新检测”。接管完成后更新为实际结果；接管失败保留可操作错误。不得由视图出现、模式切换或演示状态触发接管。

### 5.4 右侧状态舞台

主标题紧随当前状态；辅助说明限两行，详尽错误放到诊断。下方绘制“本机 Mac → 中转服务”的简洁横向路线，两端使用 SF Symbols，节点约 40 pt，间距由可用宽度决定。

服务器模式中转节点标注真实域名；临时模式使用“临时隧道”。只有已通过就绪检查，整条路线才显示完成态。过程无法独立观测时，整条路线显示等待，不捏造某个节点已通过。

路线不包含亮起的 iPhone 节点。扫码文案表示手机可以连接，而不是手机已经连接。

### 5.5 配对二维码

- 只有 `phase == .connected && qrImage != nil` 才可显示真实二维码。该逻辑必须是明确的展示条件，不能由动画局部状态决定。
- 正常状态使用“用手机扫码”标题和“打开 iPhone 上的 Pi Remote，选择扫码连接”说明。
- 码图目标尺寸约 224–240 pt；保持正方形、黑白、高对比度，不覆盖 Logo、不做渐变、不加扫描线。
- 使用 `.interpolation(.none)`，避免分数像素采样；尽可能按屏幕 backing scale 选择整数像素尺寸。
- 二维码四周白色静区至少保留 4 个模块宽。优先在二维码生成输出中明确保证静区；如现有输出已带静区，核实后避免重复裁切。白色托盘 padding 至少 20 pt。
- 圆角只属于外部白色托盘，不能侵入二维码及其静区。深色模式也必须保持白底黑码。
- 失联、取消或停止时，立即移除图像，替换为同尺寸中性占位。不要给失效码做淡出，不使用仍带真实二维码的过渡快照。
- 配对区下方显示“连接码包含访问密钥，仅供自己的设备使用”。
- 不增加二维码保存、复制 Token 或一键公开分享。截图交付使用测试凭据，并标明“演示”。

### 5.6 地址和工作区摘要

二维码下用两行轻量摘要展示：中转服务域名、工作区名称。悬停可查看完整无凭据地址和完整工作区路径。

“复制地址”复制 **手机入口** `wss://…/ws/ios`，由当前有效 Agent URL 按 EndpointValidator 转换得到；不能复制 `/ws/agent`、Token 或包含凭据的 URL。只有存在当前有效连接时启用，复制后原位显示“已复制”1.5 秒，不改变按钮宽度。辅助文字明确“手动连接还需要连接密钥”。

Cloudflare 未分配地址时显示“地址将在连接后生成”；恢复期间可以显示上次地址，但标记“暂不可用”并禁用复制。界面不得残留一个看起来仍然可用的旧临时地址。

### 5.7 诊断区域

默认折叠，只显示“诊断”和最近一条脱敏日志摘要。展开后显示日志正文与“复制诊断”按钮，当前最多 300 行的限制保留。

- 日志用等宽字体、可选择文本；长行横向滚动或合理换行，不能把窗口撑宽。
- 用户处于底部时，新日志自动跟随；用户向上查看时停止跟随，显示“回到最新”。
- 连接错误使诊断入口带错误标记，但不自动撑开面板打断用户。右侧错误区域提供“查看诊断”。
- “复制诊断”包含 App 版本、模式、当前状态、脱敏日志；不包含 Token、二维码 payload 或完整用户目录。
- 导出时统一替换当前已配置 Token、活动 Token、URL token 参数及用户主目录前缀；不能仅依赖 AppModel 当前的单一 activeToken 替换。日志未知字段不推测为安全；仅输出必要字段。
- 如果有新增日志搜索等想法，留待后续，不扩大本次实现范围。

### 5.8 菜单栏

保留原生 MenuBarExtra 菜单，不改成复杂 dashboard。显示状态、模式、打开主窗口、当前可用连接动作和退出；旧服务接管仍在检测到时显示。

图标根据状态切换，但不持续闪烁或旋转。关闭主窗口后保持连接；Cmd+Q 继续走现有等待清理的退出流程。菜单标题与主窗口状态必须一致。

## 6. 状态与文案契约

| 真实状态 | 主标题 / 辅助文案 | 配对区 | 主要动作 |
| --- | --- | --- | --- |
| `idle` 初次 | 让手机连接这台 Mac / 配置连接方式后，生成手机连接码。 | 静态 π 与连接轮廓，不能显示可扫码的假码 | 连接 |
| `idle` 主动断开后 | 已断开连接 / 设置已保留，可随时重新连接。 | 中性占位 | 重新连接 |
| `connecting` | 正在建立连接 / 使用真实连接阶段短文案 | 同尺寸等待占位，进度指示 | 取消连接 |
| `connected` | 已准备好，随时连接 / 用 iPhone 扫码，访问这台 Mac 上的 pi。 | 真实二维码 | 断开连接 |
| `recovering` | 连接暂时中断 / 正在自动重连，恢复后会重新显示连接码。 | 立即撤码，琥珀色等待占位 | 停止重连 |
| `stopping` | 正在断开 / 正在结束本次连接并清理后台进程。 | 无码，静态占位 | 正在断开…，禁用 |
| `error` | 连接未完成 / 可理解的原因与处理建议 | 错误符号与简洁说明 | 重试连接；查看诊断 |

`error` 状态只显示一个主连接动作；当前 `canDisconnect` 在 error 也可能为 true，视图不要据此同时展示“连接”和“断开”两个同等级按钮。

在 connecting 中，服务器流程可展示“准备运行环境 → 等待服务器确认”；Cloudflare 可展示“准备运行环境 → 获取临时地址 → 等待服务器确认”。完成状态仅由现有 ready 结果推进；本地健康检查与隧道地址可能并发返回，展示阶段不能被较迟的回调倒退覆盖。

不要解析 `statusDetail` 的自然语言来驱动流程。若需要阶段 UI，给 AppModel 增加小型 `ConnectionStep` 枚举，在实际事件处更新；仍以 `phase` 为整体状态权威。不得用定时器推进步骤，也不显示虚构百分比。

建议将可观测错误整理为几种用户可理解的反馈；只在有明确错误依据时分类：

- 地址格式无效：“请输入完整的服务器连接地址”，定位地址字段。
- 工作区不存在：“找不到这个文件夹，请重新选择”，定位工作区。
- pi 不可执行：“找不到 pi，请检查可执行文件路径”，展开高级设置。
- 明确收到 401：“连接密钥不匹配，请检查后重试”。
- 健康检查仅返回未就绪或通用超时：如实说“服务器未确认连接”，不推断为 Token 错误。
- 其他 Agent 占用：“服务器已有其他 Mac 连接”，保留原始诊断，不自动抢占或终止其他设备。
- 端口占用：“临时隧道所需端口被占用”，诊断显示端口和已有建议，不新增自动杀进程。

## 7. 动画规格

每个动画必须解释正在发生的变化。统一定义 `Motion` 参数，不能用动画延迟来串联网络操作。

| 场景 | 动效细节 | 时长 / 曲线 | 限制 |
| --- | --- | --- | --- |
| 主窗口首次展示 | 右侧状态标题和容器从 y=6 pt 到 0，opacity 0→1 | 240 ms，easeOut；两个区块最多错开 40 ms | 控件即时可操作，后续重绘不重复入场 |
| 模式切换 | 选中底板横向移动；字段组 opacity + y=4 pt 替换 | 180 ms，easeInOut | 禁用期间不触发；不改变焦点到隐藏字段 |
| 按钮按下 | 填充轻微变深，非二维码按钮缩放至 0.985 | 按下 90 ms，释放 140 ms，easeOut | 减少动态效果时只改颜色；焦点环保持可见 |
| 悬停 | 按钮背景、字段边界变化 | 120 ms，easeOut | 不抬升卡片，不移动文字 |
| 连接等待 | 路线上一个小标记从 Mac 向中转节点移动 | 1400 ms，linear 循环 | 仅 connecting/recovering 且窗口可见时；至多一个循环动效 |
| 首次连接成功 | 路线变成完成态；对勾描边出现 | 220 ms + 160 ms，easeOut | 由 ready 事件触发一次，不随健康轮询反复播放 |
| 二维码就绪 | 外部容器底色淡入，码图直接稳定显示 | 容器 160 ms，easeOut | 码图本身不缩放、不旋转、不模糊、不半透明 |
| 从在线进入恢复 | 状态图标/文案交叉淡入，路线改为等待 | 160 ms，easeInOut | 真实二维码在动画前立即移除 |
| 高级设置/诊断展开 | 高度与内容 opacity 同步变化 | 200 ms，easeInOut | 只对受影响容器施加，不让整个窗口跳动 |
| 复制/导入成功 | 文案原位替换、轻淡入 | 120 ms；复制提示停留 1.5 秒 | 固定宽度，提示不抢焦点 |
| 输入错误 | 边界与说明淡入 | 120 ms，easeOut | 不抖动、不闪红，不移动其他主要操作 |

实现约束：

- 支持 macOS 13，优先 `.animation(_:value:)`、`withAnimation`、局部 transition 与 Shape；不依赖 macOS 14+ `PhaseAnimator`、`symbolEffect` 或 macOS 26 玻璃 API。使用新 API 必须有完整旧系统等价实现，本次优先避免。
- 尊重 `accessibilityReduceMotion`：取消所有位移、缩放、循环运动；可保留不超过 100 ms 的颜色或淡入变化，等待状态用静态符号加文字表达。
- 尊重 `accessibilityReduceTransparency`：材质替换为实色；尊重增加对比度设置。
- 主窗口不可见、最小化、退出或 App 不活跃时暂停自定义循环。不要只依赖 `scenePhase` 判断窗口可见性，需要结合所属 NSWindow 的可见/遮挡通知，观察者随生命周期清理。
- 不用根级 `.animation` 包住整个 AppModel；不能让日志追加、健康检查和二维码撤下产生隐式动画。
- 动画开始和结束均不得调用 `connect()`、`disconnect()`、接管或网络 API。
- 已连接静止状态不保留仅为动画服务的逐帧刷新；不要用永久运行的 TimelineView 驱动整个页面。

## 8. 实现组织与数据边界

建议结构如下，按照职责拆分，规模小的同类组件可放在同一文件，避免空壳抽象：

```text
macos/Sources/PiRemote/
  Theme.swift                     语义颜色、字体、间距、按钮样式
  Motion.swift                    动画常量及减少动态效果策略
  AppModel.swift                  保留业务；仅补必要展示数据/阶段
  PiRemoteApp.swift               窗口尺寸和原生工具栏
  Views/
    ContentView.swift             主布局与共享诊断展开状态
    ConfigPane.swift              配置、模式、导入、接管和主要动作
    StatusPane.swift              六态文案、二维码与摘要编排
    MenuBarView.swift              保留原生菜单
    Components/
      ConnectionRouteView.swift   连接轨迹，纯展示
      PairingCodeView.swift       严格码图显隐、白色静区、占位
      DiagnosticsPane.swift      日志、跟随、复制诊断
      FormComponents.swift       带标签输入、模式选择、字段错误
      StatusBadge.swift          状态图标和文字
  Presentation/
    ConnectionPresentation.swift 状态→文案/样式的纯映射
    DiagnosticRedactor.swift     集中的导出脱敏（必要时）
```

连接相关事实由 AppModel 单向传给视图；高级设置展开、诊断展开、hover、复制提示属于局部展示状态。不要复制一个独立的 `isConnected` 来与 `phase` 竞争。

必要的模型补充包括：

- 只读的当前有效手机入口 URL，复用 `activeAgentURL` 和 EndpointValidator，不能暴露 `activeToken`。
- 如实现步骤条，新增真实事件驱动的 `ConnectionStep`，并使用现有 generation 机制忽略旧请求结果。
- 初次 idle 与主动断开后的 idle 如需区别，使用明确的展示原因；不要依赖字符串包含“已断开”来判断。
- 高级字段错误、复制诊断需要的类型化结果优先从既有校验返回，避免视图分析日志猜测事实。

二维码 payload 继续保持 `{"version":1,"serverUrl":"wss://…/ws/ios","token":"…"}`，不改变 iOS 解析契约。不要把展示文本、主题设置写进这份 payload。

日志目前用数组下标作为 ForEach 身份，达到 300 行后移除头部可能导致整批身份错位。本次若实现跟随滚动，为展示日志提供稳定 ID；按追加点产生 ID，不在每次 body 计算中重新生成。只做支撑该行为的最小改动。

优先使用现有 SF Symbols 和品牌资源；独立 Logo 如需打包，使用 SwiftPM `.process` 资源或明确的 App bundle 复制步骤，不依赖开发机绝对路径。SwiftPM 新增资源 bundle 时同步核对 `build.sh` 是否把该 bundle 带入 `.app`；运行产物不能从源码目录补读资源。

## 9. 预览、可访问性与键盘

建立纯展示用 fixture，覆盖六态、服务器/临时隧道、长域名、长路径、错误文案和日志滚动。使用 macOS 13 可兼容的 PreviewProvider 或 DEBUG 展示容器即可。

预览不能直接构造会读取真实 Keychain、执行 `onAppear()` 自动连接的生产 AppModel。让纯视图接受展示数据和 action closure，预览动作使用空闭包。二维码 fixture 使用专门测试 payload，不使用仓库 `.env`。

Tab 焦点按模式、地址、密钥、工作区、高级设置、连接按钮、导入、右侧操作、诊断顺序移动；隐藏字段从焦点链移除。支持 Cmd+O 导入配置、Cmd+L 展开诊断、Cmd+W 关闭窗口、Cmd+Q 正常退出。快捷键要经菜单 Commands 统一注册；Esc 只关闭系统面板或取消局部编辑，不能意外断开连接。

输入控件有真实标签和帮助文本；错误不只靠颜色表达；图标按钮有 accessibilityLabel。二维码 VoiceOver 文案为“手机连接二维码，包含连接凭据”，不要读出 payload 或 Token。连接状态改变时可发一次可访问性通知，不能每条日志都播报。

### 阶段 A：基线与静态骨架

核对工程和本方案，记录当前工作区已有修改；确认可构建，不启动第二个 Agent 争用现有在线连接。完成语义 Theme、窗口布局、输入控件和原生菜单。先用纯展示 fixtures 验证 1040 × 720 与 900 × 640 的排版。

### 阶段 B：接入真实状态和配置

绑定原 AppModel；实现双模式、字段禁用、导入、路径选择、旧服务提示、六态动作、二维码显隐、手机地址复制、诊断基础功能。必要时增加小型展示模型；不更改网络和进程生命周期。

完成标志：真实操作路径可跑通；模拟或 fixture 状态下没有假在线、重复主操作、过时二维码。

### 阶段 C：动画与可访问性

按第 7 节逐项添加局部动画，落实减少动态效果、窗口隐藏暂停、原生焦点与键盘。最后补日志跟随、脱敏复制、长文本与错误排版。

完成标志：每个动画均有状态触发和停止条件；持续在线时画面静止；撤码不受动画影响。

### 阶段 D：构建、真实验证和交付

运行最小必要验证与现有验收脚本，整理打包产物、截图和变更说明。真实联网测试应使用用户同意的操作窗口，避免让当前生产连接被新实例替换；优先用本地隔离 Relay 验证错误、恢复和取消路径。

本次文档不是部署授权；实现不需要修改东京服务器。若后续确有服务器变更需求，应另行说明，并遵守项目服务器备份规则。

## 14. 增补范围（2026-09-26）

### 14.1 一键部署 Relay

服务器模式下分两种来源，用左栏模式控件下方的二级分段控件切换：「已有服务器」（现有的地址 + 连接密钥）与「部署到我的服务器」。

「部署到我的服务器」字段：服务器地址（IP 或主机名）、SSH 端口（默认 22，放高级）、用户名（默认 root）、SSH 私钥文件（文件选择器，只存路径，不读入或复制私钥内容）、域名（可选）。域名留空时，按服务器 IPv4 自动使用 `a-b-c-d.sslip.io`，字段下方说明"留空将使用 sslip.io 免费域名，需服务器 IP 固定"。

约束：

- 只支持密钥登录，`BatchMode=yes`，不支持密码。需要私钥口令时提示先用 `ssh-add` 加入钥匙串代理。
- 首次连接先获取主机指纹，在界面上显示指纹并由用户确认后，写入应用自己的 known_hosts（`~/Library/Application Support/Pi Remote/known_hosts`）；之后 `StrictHostKeyChecking=yes`。指纹变化时拒绝并提示，不自动覆盖。
- 服务器预检只检查、不安装：Linux、架构、Docker、Docker Compose、root 或免密 sudo、80/443 是否被非本项目进程占用、`/opt/pi-remote` 是否为非受管目录。任一不满足则列出原因与处理建议，不修改服务器。
- 只做 standalone 模式（内置 Caddy + 自动证书）。端口被占用时提示需要手动 external-proxy 部署，不自动处理。
- 部署步骤：确认指纹 → 预检 → 上传部署包 → 执行 `install-server.sh`（服务器上构建镜像）→ 读取服务器 `.env` 中的 Token → 等待公网 `https://<域名>/api/health` 就绪。完成后把 `wss://<域名>/ws/agent` 写入服务器地址、Token 写入钥匙串，切到「已有服务器」并自动连接。
- 服务器已有受管安装时视为升级，安装器会保留原 Token；界面在开始前明确显示"将升级已有部署"。
- 部署期间右侧状态舞台显示真实部署步骤与取消按钮；诊断区显示脱敏后的部署日志（不含 Token）。取消会终止本机 ssh 进程，界面说明服务器上可能已完成部分步骤，安装器自身会回滚未完成的升级。
- 部署是修改服务器的操作，点击「部署」后先显示确认面板（目标主机、域名、首装/升级），确认后才执行。

### 14.2 运行时 pi / omp

高级设置中增加「运行时」分段控件：pi / omp。切换时如果可执行文件仍是另一运行时的默认路径，则自动替换为本运行时默认路径（pi：`/usr/local/bin/pi`；omp：`~/.local/bin/omp`），用户自定义过的路径不覆盖。Agent 通过环境变量 `PI_RUNTIME=pi|omp` 获知运行时。右侧摘要行显示"运行于本机 · <运行时> · <工作区>"。终端桥同时支持 pi 与 omp 的终端会话，与此选项无关。
