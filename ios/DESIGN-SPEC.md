# Pi Remote iOS · 前端设计规格（Liquid Glass）

本文件由设计稿 `/Users/mac/Downloads/Pi Remote · iOS Liquid Glass.fig` 的二进制节点树自动提取整理而成，是 iOS 客户端的实现依据。

原始提取物（机器生成，含全部图层与坐标）：

- `/tmp/pi-remote-fig/spec.txt`：每屏的 frame/图层清单 + 全部文本（绝对坐标、字号、字体、颜色）
- `/tmp/pi-remote-fig/fills.txt`：每屏所有填充节点的绝对坐标、尺寸、颜色（含渐变标记）

## 3. 与 Relay 后端的对接契约

后端（`/Users/mac/Desktop/pi-remote` 的 Node/TS Relay）不改动，iOS 端按下述协议接入：

- 端点：`/ws/ios`（WebSocket），鉴权用 `Authorization: Bearer <IOS_TOKEN>` 头（或 URL query `token`）。
- 握手：`{"version":1,"type":"hello","deviceId":"<设备名>","payload":{"role":"ios"}}`，role 必须为 `ios`。
- 请求：`{"version":1,"type":"request","requestId":"r1","sessionId":"<可选>","payload":{"method":"<方法>","params":{...}}}`；可用方法：`subscribe`、`unsubscribe`、`session.list`、`session.start`（params.cwd 相对 `PI_WORKSPACE_ROOT`）、`session.prompt`（params.message）、`session.abort`、`ui.response`（params.requestId + params.response）。
- 响应：`{"version":1,"type":"response","requestId":"r1","sessionId":"...","payload":{"ok":true,"data":{...}}}`，失败为 `payload.ok=false` 且带 `error.code`。
- 事件：`session_event` 帧，`payload.event` 为归一化事件，含 `sessionId`；事件类型含 `text_delta`（增量文本）、思考、工具调用、`ui_request`（工具/扩展请求确认，需用 `ui.response` 回答）。
- 已确认限制：`session.prompt` 返回只代表入队；事件无持久化/重放；`message_update` 的增量需要客户端自行拼接。

UI 映射：`connect` → 连接与配对；`sessions` → `session.list` 结果列表；`new` → `session.start` + `session.prompt`；`running` → `text_delta`/思考/工具事件流式渲染；`approval` → `ui_request` 弹层 → `ui.response`；`done` → 回合结束、diff 与测试结果。

## 4. 验收标准

1. `xcodebuild -project ios/PiRemote.xcodeproj -scheme PiRemote -sdk iphonesimulator build` 成功。
2. 6 个页面均可在模拟器上打开，导航关系与设计一致（connect → sessions → new → running → approval → done）。
3. 所有设计稿文案逐字出现，字号/颜色按第 1、2 节取值。
4. 真实协议接入：连接、会话列表、新建会话、流式输出、确认弹层、停止/中止可用，未接通状态下有明确的错误提示，不出现假数据冒充真实结果。
